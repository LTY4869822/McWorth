# McWorth 实战验证报告（v0.2.1）

> 验证方式：以真实用户身份，用**真实 MCP 实时数据**、走**正式 CLI 命令**（plan → ingest-quotes → report）
> 跑全新场景，再独立手算核对结论。证据全部落盘于本目录，可复核。
>
> 验证时间：2026-10-16　门店：深圳松坪山餐厅（1421057），到店自取。该店菜单 86 个商品，
> 与包内演示快照（门店 1450713，32 个商品）完全不同，属于全新数据。

## 一、三个场景的实际结果

| 场景 | 用户诉求 | 官方核价基准 | McWorth 结论 | 人工复核 |
|---|---|---|---|---|
| A | 35 元内：双层吉士汉堡+薯条，不接受加量 | ¥37.00 | 超出预算，建议放宽到 ¥37.00 或授权更换 | ✅ 23+14=37 正确 |
| B | 35 元内：麦辣鸡腿汉堡+薯条，允许加量 | ¥36.50 | 主推荐 ¥33.50（三件套，多出可乐中杯），标注"方案差额低 ¥3.00" | ✅ 22.5+14=36.5；三件套 33.5 |
| C | 同上 + 允许替换薯条 + 纳入随心配 | ¥37.00 | 主推荐 ¥28.90（中薯条 + 随心配含双层吉士汉堡/红茶，多出红茶） | ✅ 14+14.9=28.9 |

全部金额与菜单标价、官方 calculate-price 返回值逐项对得上；每次调用都有 traceId 可查。
**反直觉结论在新门店复现**：麦辣鸡腿汉堡+薯条单品 ¥36.50，三件套 ¥33.50——多一杯可乐反而便宜 ¥3.00，
且默认策略（extras_policy=disallow）**不会**把它当推荐，只有明确授权后才作为"方案差额"展示。

## 二、信任机制的实测

| 测试 | 结果 |
|---|---|
| 篡改 `session_id` | ✅ 被拒绝："身份不符（session_id 与计划不一致）——cart_hash 匹配不构成身份证明" |
| 篡改 `intent_revision` | ✅ 被拒绝，理由同上 |
| 篡改金额（总价改成 1 分，明细不变） | ❌ **被接受，并作为主推荐输出"官方整单核价 ¥0.01"** |

## 三、发现的缺陷（按严重度）

### D1｜报价缺少"自洽性"校验（建议修复）
四元组校验解决了"这条报价属于哪个请求"，但没有解决"这条报价自己是否自相矛盾"。
实测：把 `total_fen` 改成 1 分而 `product_price_fen=4800`、明细合计 4800 的响应，
ingest-quotes 接受、report 输出 ¥0.01 为主推荐——**违反产品自己立的不变量 ③（进入推荐的金额必须来自官方整单核价）**。

可行修复：在 ingest-quotes 增加金额自洽校验：
`total == product_price - discount + delivery + packing + tableware`（缺失项按 0/未知处理），
且 `product_price == Σ items.subtotal`；不一致即拒绝并给出原因。风险低、可加回归测试。

### D2｜"该抓哪些套餐"没有策略指引（影响结果质量）
`plan --combos` 需要宿主自己决定抓哪些套餐详情，而 SKILL.md 未给出发现策略。
实测差别巨大：同一诉求，只用"名字含目标餐品"的套餐 → 结论"无解，最低 ¥37"；
把随心配（1+1 类商品）也纳入 → 结论变成"¥28.90"。**结论的正确性取决于宿主的枚举覆盖**。
建议在 SKILL.md 补一节"套餐发现清单"（至少覆盖：单品、同名套餐、三件套/四件套、随心配/1+1、加价购）。

### D3｜展示没有收敛到"最多三个有意义的选择"
SKILL.md 第 4 节要求最多展示三个有意义选项，实卡一次列了 7–9 行（含 ¥80 的明显无关组合）。
建议：候选按"同餐盘 → 增量 → 替换"分组，每组只留最省的 1–2 条。

### D4｜文档小缺口
- `extras_policy` 的取值是 `disallow`/`allow`，SKILL.md 从未写明（我用 `deny` 直接报错）。
- `ingest-quotes` 输出的键名是 `records`/`errors`，文档只说"报价记录"。
- `responses.json` 的 `context_key` 取自 `plan.context.context_key`（不在 quote_requests 内），
  文档措辞容易让宿主取错（我第一次就取错了）。

## 四、可用性评估（新鲜用户视角）

- 全新 venv 安装 wheel：✅ 一次成功（走腾讯云镜像），`doctor` 全绿，`demo` 一键出结论。
- 依赖极简（仅 pydantic），Windows 含空格路径无问题。
- 主要门槛不在安装，而在**宿主编排**：三个命令 + 两个文件格式 + 四元组抄录，写对了很稳，
  但初次接入容易在 `context_key` 取值、套餐发现范围上栽跟头（D2/D4）。

## 五、结论

**这个东西是真有用的**：它给出的价格全部可复核，身份校验能挡住错会话/错版本的报价，
默认不替用户做"加量换便宜"的决定——这三点在真实门店数据上验证成立，
且确实找到了人肉不会去算的最省买法（¥36.50 → ¥28.90，低 ¥8.10）。

**但它现在还不是"可以无条件信任"的**：D1 是一条真实存在的错误金额进入主推荐的路径，建议在 v0.2.2 修掉并补回归测试。
D2 决定了它的答案质量上限，建议把"套餐发现清单"写进 SKILL.md——否则不同宿主跑出的结论可能天差地别。
