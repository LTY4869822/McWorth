# 麦麦如意餐 McWorth

> **保住你想吃的，找到更省的买法。**

在麦当劳点餐时，同一份餐盘往往有多个买法：单品直购、换成套餐、换哪种套餐。价格差常常藏在这些组合里，人工比价既慢又不完整。

McWorth 把"吃什么"和"怎么买"拆成两件事分别计算：**目标餐盘**不变的前提下，枚举并用麦当劳官方 MCP 逐单核价，最后给你一张可以复核的结果卡。

---

## 一个真实案例（来自官方 MCP 实测数据）

> 用户：*"35 元以内，我就想吃麦辣鸡腿汉堡和中薯，我自己带了水。"*

| 购买路径 | 实际到手 | 官方整单核价 |
|---|---|---:|
| 单品直购（用户原计划） | 麦辣鸡腿汉堡 + 中薯条 | **¥36.00** |
| 麦辣鸡腿汉堡三件套 | 麦辣鸡腿汉堡 + 中薯条 **+ 可乐中杯** | **¥33.50** |

套餐便宜 ¥2.50，但**多出一杯你原本不需要的饮料**。

McWorth 的默认处理是：**不推荐它。**

```text
$ mcworth demo

保留：麦辣鸡腿汉堡×1、中薯条×1
目标餐盘摘要：plate:sha256:a38702e712cc42b1

baseline · 相同餐盘 · 官方核价 ¥36.00
combo-default · 餐盘有增量 · 官方核价 ¥33.50（多出：可乐中杯×1）

求解状态：SEARCH_EXHAUSTED
在本轮核价范围内，没有同时满足这些要求的方案（预算 ¥35.00）。
保留当前餐盘的最低核价为 ¥36.00；你可以把预算调整到 ¥36.00，
或允许更换餐品后重新查看。
```

只有当你明确授权，方案差额才会被展示为可选项——**而且措辞会随之改变**：

```text
$ mcworth demo --extras-policy allow

── 与单品分别购买相比 ────────────────
对照基准（单品分别购买）核价：¥36.00
与单品分别购买相比：低 ¥2.50（注意：餐盘不完全一致，这是方案差额，不是无代价节省）
```

注意基准的说法：这个对照是**系统构造的全单品直购**，不是"你的原计划"——因为本轮你并没有告诉我们你原本打算怎么买。只有你提供了原购物车，我们才会说"与您的原计划相比"。

这不是文案洁癖。餐盘一旦变了，"省了多少"就是个错账。

---

## 五条不变量

这些是产品的硬边界，全部有测试守护：

1. **预算是支出上限，不是必须花光的目标。**
2. **用户锁定的餐品、规格和排除要求不会被暗中放宽。**
3. **进入主推荐的金额必须来自官方整单核价**——本地估算只用于排序候选，不能充当报价。
4. **省钱说明必须对应可比基准**；换餐、换规格、换履约产生的只是方案差额。
5. **没有基准就不报省了多少**；报价不可用时也不冒充实付金额。

## 安装

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install dist/mcworth-*.whl     # 或源码安装：pip install -e ".[dev]"
```

前置条件：已在宿主客户端（如 WorkBuddy / Claude Desktop / Cursor）配置好麦当劳 MCP 连接。配置模板见 [`mcp-config.example.json`](./mcp-config.example.json)，**其中只含变量名占位符，请务必不要把真实 Token 提交入库**。

## 使用

### 三个只读命令（宿主编排协议）

McWorth 的核心是三个命令之间的 JSON 文件交接，**全程不发起网络调用**——联网部分（调 MCP 工具）由宿主 Agent 完成：

```text
mcworth plan        意图+菜单 → 候选组合 + 核价请求（request_id / cart_hash + official_payload）
mcworth ingest-quotes  官方核价响应 → 身份与商品对账校验后的报价记录
mcworth report      → 可复核结果卡（分类、措辞、基准、时效、traceId）
```

宿主侧的完整编排方式（含 responses.json 逐字段说明）见 [`skills/mcworth/SKILL.md`](./skills/mcworth/SKILL.md)。

**报价可信规则（v0.2.1）**：核价响应必须携带与 plan 一致的 `request_id` / `session_id` / `intent_revision` / `context_key`，且返回的商品清单要与请求对账——cart_hash 匹配不构成身份证明，错任务、错门店、错商品的响应一律拒绝。`live` 报价超过 6 小时新鲜度阈值（本地复查策略，非官方保价承诺）不再支撑主推荐；历史回放与合成演示会在结果卡上明确标注，不会伪装成实时价格。

### 本地演示

```bash
mcworth doctor                # 环境自检（只报能力结果，不打印凭证）
mcworth demo                  # 用官方 MCP 实测快照跑一遍求解
mcworth demo --extras-policy allow   # 明确授权后，看看接受套餐增量会发生什么
```

> `demo` 的数据来自包内留存的真实 MCP 响应快照（含官方 traceId 与采集时间），**不发起网络调用**。这意味着你可以在完全离线的环境里复现上文的结论，也意味着它不会替你下任何单。

## 目标用户

- **经常点麦当劳、想知道自己有没有买贵的人**——不需要记住一堆套餐规则。
- **有明确偏好的人**——"我就要这个堡和这个薯"，不喜欢被推荐流引导去换更贵的组合。
- **对"优惠"天然警惕的人**——反感先涨后降、反感"多送一杯所以更便宜"的话术。

## 当前状态与边界

**已完成（v0.2.1）**：固定餐盘模式全链路。读取真实菜单 → 解析套餐轮次结构（回溯搜索处理 min=0 可选轮 / min>1 强制多选 / 选项级数量上限）→ 构造候选购买组合（含用户授权的加购选项）→ 官方整单核价（身份四元组 + 商品清单对账，live 报价时效检查）→ 分类（相同餐盘 / 增量 / 替换）→ 按策略与偏好过滤排序 → 输出可复核结果卡（回放/演示模式明确标注）。

57 项测试守护五条不变量，其中 35 项来自两轮独立审查反例的回归组。

**尚未实现**：优惠券与卡券参与计价、多餐盘预算配餐模式、订单创建。这些都还在设计阶段——README 里没写的就没有，不会悄悄上线。

**明确不做**：自动下单。执行涉及真实支付与账户权益，在对齐安全边界前保持只读。

更多取舍说明见 [`docs/w1-feasibility.md`](./docs/w1-feasibility.md) 与 [`docs/tool-schemas.md`](./docs/tool-schemas.md)。

## 项目结构

```text
src/mcworth/
├── domain/      # 意图、餐盘、报价、证据（金额一律整数分）
├── adapters/    # 官方响应 schema → 内部类型（严格金额校验）
├── solver/      # 固定餐盘的回溯求解、合格性判定与偏好排序
├── evidence/    # 差额记账与结果卡渲染（baseline_origin）
├── data/        # 包内演示快照（安装即用）
└── cli.py       # plan / ingest-quotes / report / demo / doctor
tests/
├── contract/    # 官方响应结构漂移守护
├── solver/      # 五条不变量的可执行定义
├── regressions/ # 审查反例回归组（24 项）
└── fixtures/    # 脱敏的官方实测快照
```
